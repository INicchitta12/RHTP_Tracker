WHAT IS COMMITTED, AND WHAT IS NOT. Each file under releases/ is the
<main> element plus the schema.org JSON-LD, NOT the page as served.
CMS's page chrome carries a third-party Mapbox API token in its Drupal
settings JSON, which is CMS's to publish and not ours to redistribute;
this is the posture §7.1 took for the allotment table and Session 11
took for the six state press releases. The JSON-LD is kept because it
is where CMS publishes the topic -- archiving <main> alone would throw
away the field the filter reads and leave the archive unre-parseable
offline. Every file was asserted free of that token shape before it was
written, and the full page's digest is recorded per release in
data/reference/cms_newsroom_topic_index.csv (full_page_sha256), so
provenance still closes against what cms.gov served.

The listing pages under listing/ carry no such token and ARE archived
byte for byte as served.

Digests are written with writeBin, not writeLines: writeLines appends a
trailing newline, so the file on disk would be one byte longer than the
body that was hashed and a reader verifying it would get a mismatch.

THE TOPIC FILTER is CMS's own, read from each release's schema.org
NewsArticle JSON-LD `about`. CMS's facet URL for the same taxonomy,
/newsroom/search?about[]=<id>, is refused by Akamai for any
non-browser client (403 on the bare path, with no query string), so
the topic is read from the document instead of from a query.

A DISCOVERY source (§0.1). No figure here may enter an AHA-published
number, and `amount` is never summed (§0.2): CMS mixes the Tier 1
state allotment and the Tier 3 announcement in the same release --
Virginia's names $122M in its headline and $189M in a quoted
statement, and those are two different tiers of the same programme.

sha256 per file. MANIFEST.txt IS NOT LISTED IN ITSELF -- a manifest
cannot record its own digest, because the value would be stale the
instant the file is written. It listed itself until a second --run on
one archive date exposed it: the first run wrote the manifest AFTER
taking the listing, so the file did not exist to be listed and the
verification test passed on absence rather than on correctness.
